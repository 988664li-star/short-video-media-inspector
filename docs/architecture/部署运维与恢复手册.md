# 部署、运维与恢复手册

## 1. 第一阶段拓扑

```text
Internet
  → Nginx
    ├─ frontend（React 静态文件）
    └─ api（FastAPI）
         ├─ MySQL
         ├─ Redis
         └─ MinIO
```

第一阶段使用 Docker Compose。不要因服务数量提前引入 Kubernetes；只有多机部署、独立扩缩容和高可用需求明确后再迁移。

## 2. Compose 服务清单

| 服务 | 是否持久化 | 健康检查 | 备注 |
| --- | --- | --- | --- |
| `nginx` | 否 | HTTP | TLS、前端、反向代理 |
| `frontend` | 否 | HTTP | 构建后静态文件 |
| `api` | 否 | `/api/v1/health` | FastAPI API |
| `mysql` | 是 | `mysqladmin ping` | 具名 Volume、定时备份 |
| `minio` | 是 | `/minio/health/live` | 私有 Bucket、生命周期策略 |
| `redis` | 视用途 | `redis-cli ping` | 会话与缓存需设置内存上限 |

## 3. 日常命令（待实现）

```text
make up          启动基础设施和应用
make down        停止服务（不删除 Volume）
make logs        查看聚合日志
make migrate     执行 Alembic migration
make test        运行单元和集成测试
make backup      创建 MySQL + MinIO 备份
```

## 4. 备份与恢复

| 数据 | 备份方式 | 验证 |
| --- | --- | --- |
| MySQL | 定期逻辑备份 + 生产环境时间点恢复策略 | 每月至少一次恢复演练 |
| MinIO | Bucket replication 或离线对象备份 | 抽样恢复并校验对象 hash |
| Redis | 不作为唯一事实来源 | 可清空并从 MySQL 重建关键缓存 |

## 5. 关键监控与告警

- API：5xx 比例、P95 延迟、认证失败率、限流命中率。
- AI 调用：运行中请求数、耗时、超时和失败率。
- MySQL：连接数、慢查询、磁盘、备份失败、迁移状态。
- MinIO：容量、上传失败、预签名失败、对象生命周期清理失败。
- 支付：回调验签失败、待支付超时、重复回调、积分发放失败。

## 6. 故障处理原则

| 场景 | 处理 |
| --- | --- |
| API 进程重启 | 中断中的本地处理请求由客户端重试；最终任务状态以 MySQL 记录为准 |
| 支付回调失败 | Provider 重试；同时提供订单主动查询补偿任务 |
| 结果状态不明确 | Job 转 `REVIEW_REQUIRED`；查询供应商状态后结算或退款 |
| Redis 丢失 | 会话按策略重新登录；缓存从 MySQL 重建 |
| MinIO 不可用 | 暂停上传/新任务；不将任务误标记成功 |

## 7. 上线检查

- 数据库 migration 已在预发环境验证。
- 生产密钥已通过 Secret Manager 注入，未出现在镜像、日志或前端构建产物。
- HTTPS、回调域名、CORS、Cookie 域和预签名 URL 域已验证。
- 微信支付/支付宝使用真实回调与重复回调测试。
- MySQL、MinIO 备份和恢复演练已完成。
- 基础告警和 On-call 负责人已明确。
