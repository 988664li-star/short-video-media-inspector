# 配置、安全与权限规范

## 1. 配置原则

- 所有环境差异通过环境变量或受审计的后台配置管理，不在代码中写死。
- `.env` 只用于本地开发；仓库只提交 `.env.example`。
- 密钥只存在 Secret Manager、部署平台 Secret 或本机安全环境；绝不写入日志、接口响应、数据库明文字段或前端包。
- 商品、积分、能力价格、并发、上传限制和支付 Provider 开关属于**业务配置**，管理员修改须记录审计日志。

## 2. 环境变量清单

| 分类 | 变量 | 示例 / 说明 |
| --- | --- | --- |
| 应用 | `APP_ENV` | `development` / `test` / `production` |
| 应用 | `API_PREFIX` | `/api/v1` |
| MySQL | `MYSQL_DSN` | 仅服务端可读 |
| MinIO | `MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY` | 私有 Bucket；生产使用 HTTPS |
| Redis | `REDIS_URL` | 会话、限流、缓存 |
| RabbitMQ | `RABBITMQ_URL` | API 与 Worker 使用不同账号/权限 |
| Auth | `JWT_SIGNING_KEY`、`ACCESS_TOKEN_TTL_SECONDS`、`REFRESH_TOKEN_TTL_SECONDS` | 默认 15 分钟 / 30 天 |
| Auth | `AUTH_MAX_ACTIVE_SESSIONS` | 默认 `5` |
| Email | `EMAIL_PROVIDER`、`EMAIL_FROM`、`EMAIL_API_KEY` | 邮箱验证和通知 |
| Payment | `WECHAT_PAY_*`、`ALIPAY_*` | 私钥、证书、回调验签配置，不进入前端 |
| AI | `SILICONFLOW_API_KEY`、`ARK_API_KEY` 等 | 沿用现有 Provider 配置；不可记录到日志 |
| Observability | `OTEL_EXPORTER_OTLP_ENDPOINT`、`SENTRY_DSN` | 可观测性后端地址 |

## 3. 后台业务配置

### 3.1 可配置项

| 配置域 | 必填项 |
| --- | --- |
| 积分商品 | 名称、售价、赠送积分、有效期、启用状态、展示排序 |
| 能力目录 | `capability_code`、启用状态、最大并发、文件大小/时长、保留天数 |
| 计价规则 | 规则类型、参数、版本、生效时间、预扣策略 |
| 支付渠道 | Provider 开关、商户配置引用、回调地址、沙箱/生产模式 |
| 运营规则 | 新用户试用积分、活动赠送、失败退款策略、人工补偿权限 |

业务配置需要版本号与生效时间。创建任务、订单或账本时保存对应配置快照，历史记录不受后续修改影响。

## 4. 身份认证与会话安全

- 仅支持邮箱注册和登录；邮箱需验证后才能进入 `ACTIVE` 状态。
- 密码使用 Argon2id 哈希；登录、注册、验证邮箱接口需 Redis 限流。
- Access Token 为短期 JWT；Refresh Token 为随机不透明值，仅保存哈希，使用 HttpOnly + Secure + SameSite Cookie。
- 每设备独立 Session，默认最多 5 台设备；超限时撤销最早活跃 Session。
- 退出单设备、退出全部设备、重置密码、封禁账户均要在 MySQL 和 Redis 中撤销会话。
- 访问控制包含：身份、资源归属、能力规则三层校验。

## 5. 文件与对象存储安全

- MinIO Bucket 默认私有；浏览器仅通过短期预签名 URL 上传或下载。
- 后端检查对象路径、文件大小、MIME、校验和与项目归属。
- 不接受用户提交的任意第三方下载 URL 作为 AI 输入。
- 对视频、音频、图片分别配置最大尺寸和时长；预留恶意文件扫描接口。
- 所有对象路径必须包含环境、用户和项目隔离前缀。

## 6. 支付安全

- 浏览器支付完成跳转页不改变订单状态；只有 Provider 服务端 Webhook 可将订单改为 `PAID`。
- 回调必须校验签名、金额、货币、商户订单号、订单当前状态与 Provider 交易号。
- 支付回调按 Provider 交易号幂等；重复回调不能重复发积分。
- 金额使用 decimal/最小货币单位，禁止浮点数。
- Webhook 原始载荷需要脱敏保存，便于审计；签名、私钥不得入库或写日志。

## 7. 日志、审计和隐私

- 每个 HTTP 请求和 MQ 事件带 `request_id` / `trace_id`。
- 日志中禁止记录密码、验证码、access/refresh token、Cookie、支付签名、API Key、原始支付凭据。
- 管理员改价、改配置、人工补偿、退款、订单状态修正必须写审计日志。
- 用户删除与资产保留策略需区分：业务记录可匿名化，媒体对象按生命周期删除。
