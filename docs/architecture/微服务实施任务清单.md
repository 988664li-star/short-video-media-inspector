# 微服务实施任务清单

> 本清单将已确认的架构和业务规则转化为开发任务。目标是先交付一条完整可用闭环，再逐步扩展支付、运营后台与微服务拆分。

## 0. 当前已完成的设计工作

- [x] 微服务服务边界与基础设施选型。
- [x] MySQL、MinIO、Redis、RabbitMQ 的职责定义。
- [x] 邮箱注册、登录、可配置多端会话流程。
- [x] 积分购买、支付回调、积分账本、退款流程。
- [x] AI 能力调用、预扣、Worker 执行、结算与结果回传流程。
- [x] Web API 调用地图和架构图。

已确认的业务基线：邮箱登录；默认 5 端登录且可配置；积分优先；用户主动取消不退款；系统/供应商失败自动退款；微信支付和支付宝；第一阶段不做团队账号。

## 1. 总体交付路径

```text
P0 接口和数据设计
→ P1 基础环境
→ P2 用户与会话
→ P3 项目与文件
→ P4 异步 AI 任务闭环
→ P5 积分账本
→ P6 微信/支付宝支付
→ P7 管理配置与通知
→ P8 测试、安全、监控与发布
```

**最小可用闭环（MVP）**：

```text
邮箱注册登录
→ 上传视频到 MinIO
→ 创建转写任务
→ 校验并预扣积分
→ RabbitMQ 投递任务
→ AI Worker 执行
→ 写入结果和最终积分结算
→ Web 查询或实时获得结果
```

支付、运营后台和更多 AI 能力建立在此闭环之上。

## 2. P0：接口和数据设计（必须先完成）

### 2.1 OpenAPI 接口契约

**任务**

- [x] 新建 [`docs/api/开放接口规范V1.yaml`](../api/开放接口规范V1.yaml)，作为前后端共同接口事实来源。
- [x] 定义通用响应、分页、错误码、`request_id`、`Idempotency-Key`。
- [x] 定义认证、项目/资产、任务、积分、支付、通知接口的 v1 草案。
- [ ] 实现前逐条评审 OpenAPI，并将 FastAPI/Pydantic Schema 与契约对齐。

**完成标准**

- 前端可以仅依据 OpenAPI 开发请求层和 Mock。
- 所有写操作均明确是否要求 `Idempotency-Key`。
- 所有异步任务接口明确返回 `202 + job_id`。

### 2.2 MySQL 数据模型与迁移

**任务**

- [x] 新建 [`docs/architecture/MySQL数据模型与迁移规范.md`](./MySQL数据模型与迁移规范.md)，定义 ERD、字段、索引和外键边界。
- [ ] 确定数据库拆分：`user_db`、`project_db`、`task_db`、`billing_db`；第一阶段可运行在一个 MySQL 实例中。
- [ ] 选用 SQLAlchemy 2.x 和 Alembic，建立迁移目录与首个版本。
- [ ] 定义枚举：用户、会话、任务、订单、支付、积分账本、Outbox 状态。
- [ ] 为订单、支付回调、任务创建、账本写入建立唯一幂等索引。

**核心表**

```text
users, email_verifications, user_sessions, roles, user_roles
projects, assets, analysis_jobs, job_results
products, orders, payment_transactions, credit_ledger, credit_balance_snapshots
outbox_events, processed_events, notifications
```

**完成标准**

- `alembic upgrade head` 可在空 MySQL 实例创建全部表。
- 每一个状态变化与积分变化都能追溯到业务 ID 与操作时间。

### 2.3 后台配置模型

**任务**

- [ ] 设计管理配置表或配置后台：积分商品、能力目录、价格规则、任务限制、支付 Provider 开关。
- [ ] 为能力定义版本化价格规则：`fixed`、`per_input_minute`、`per_scene`、`per_output_second`、`by_model`、`formula`。
- [ ] 任务创建时持久化报价快照，防止后续改价影响历史任务。
- [ ] 将 `AUTH_MAX_ACTIVE_SESSIONS=5` 设为环境/后台配置，而非硬编码。

**完成标准**

- 管理员调整价格、并发、文件限制后，新任务按新规则报价；历史任务不变。

## 3. P1：本地与测试环境基础设施

### 3.1 Docker Compose

**任务**

- [ ] 新建 `docker-compose.yml` 或 `deploy/compose/`。
- [ ] 运行 MySQL、MinIO、Redis、RabbitMQ、FastAPI API、AI Worker、前端和 Nginx。
- [ ] 所有服务使用具名 Volume；不要把持久化数据放进仓库。
- [ ] 为 MySQL、MinIO、Redis、RabbitMQ 配置健康检查。
- [ ] 提供 `make up`、`make down`、`make logs`、`make migrate` 等开发命令。

### 3.2 配置与密钥

**任务**

- [ ] 编写 `.env.example`，只包含变量名和安全说明，不包含真实密钥。
- [ ] 拆分开发、测试、生产配置。
- [ ] 配置 MySQL、MinIO、Redis、RabbitMQ、JWT、邮件、微信支付、支付宝、AI Provider 变量。
- [ ] 生产环境使用 Secret Manager/KMS；不将 Cookie、支付密钥、AI Key 写入日志或数据库明文。

**完成标准**

- API 健康检查能识别依赖不可用，而不泄露密钥。

## 4. P2：用户、邮箱验证与会话

**后端任务**

- [ ] 实现邮箱注册、验证码发送与邮箱验证。
- [ ] 使用 Argon2id 哈希密码；限制登录/验证码请求频率。
- [ ] 实现 JWT access token（15 分钟）和轮换 refresh token（30 天）。
- [ ] `refresh_token` 只保存哈希，Web 端使用 HttpOnly Secure Cookie。
- [ ] 实现设备会话列表、单设备退出、全部退出。
- [ ] 实现达到登录上限时踢出最早活跃设备。
- [ ] 网关统一校验 Token、注入 `user_id` 和 `request_id`。

**前端任务**

- [ ] 注册、邮箱验证、登录、忘记密码（可后置）、账户设置页面。
- [ ] 请求拦截器自动携带 access token；401 时仅尝试一次刷新。
- [ ] 设备管理页面。

**验收标准**

- 用户能完成邮箱注册和验证后登录。
- 同一用户在第 6 台设备登录时，最早设备被安全注销。
- 单设备退出不影响其他设备；全部退出使所有 refresh token 失效。

## 5. P3：项目、资产与 MinIO

**后端任务**

- [ ] 实现项目 CRUD 和资源归属检查。
- [ ] 实现 MinIO Bucket 初始化、私有策略、生命周期规则。
- [ ] 实现预签名上传、确认上传、预签名下载。
- [ ] 创建 `assets` 表，保存对象键、大小、类型、校验和、归属项目/用户。
- [ ] 限制 MIME 类型、文件大小、视频时长；拒绝任意外部 URL。
- [ ] 将新增媒体资产从本地 `backend/data/` 改为写入 MinIO；旧数据采用迁移脚本逐步转移。

**前端任务**

- [ ] 上传进度、失败重试、上传完成确认。
- [ ] 项目列表、项目详情、资产选择。

**验收标准**

- 大文件由浏览器直接上传 MinIO，不经 FastAPI 流转全部字节。
- 用户无法通过 asset ID 下载其他用户的文件。

## 6. P4：异步 AI 任务闭环

**后端任务**

- [ ] 引入 RabbitMQ，定义 `analysis.requested`、`analysis.completed`、`analysis.failed` 事件。
- [ ] 建立 AI Worker 进程；先迁移“转写”作为首条能力。
- [ ] Worker 从 MinIO 读取输入，执行，写入 MinIO/MySQL。
- [ ] 实现任务状态机：`CREATING → PENDING → RUNNING → SUCCESS / FAILED / CANCELED`。
- [ ] 实现 `outbox_events` 发布器、消息幂等、手动 ack、重试、死信队列。
- [ ] 实现任务状态查询；先用轮询，后续接 SSE/WebSocket。
- [ ] 添加任务超时、供应商异常和人工补偿入口。

**验收标准**

- API 在创建任务后立即返回 `202 + job_id`。
- Worker 重启后不会丢失未完成任务；重复消息不重复生成结果。
- 任务完成后浏览器可获取结果及 MinIO 短期下载地址。

## 7. P5：积分账本与能力计价

**后端任务**

- [ ] 实现商品、能力目录和价格规则配置读取。
- [ ] 实现积分账本：`CREDIT_GRANT`、`CREDIT_RESERVE`、`CREDIT_SETTLE`、`CREDIT_REFUND`、`CREDIT_EXPIRE`。
- [ ] 创建任务时同一事务写入 Job、`CREDIT_RESERVE` 与 Outbox。
- [ ] 成功后结算；系统/供应商失败全额退款；用户 `PENDING` 取消默认不退款。
- [ ] 对状态不确定任务设 `REVIEW_REQUIRED`，由补偿任务查询供应商后处理。
- [ ] 提供余额、账本、能力报价查询接口。

**前端任务**

- [ ] 余额展示、能力预计消耗展示、创建任务二次确认。
- [ ] 积分明细页：来源、预扣、消耗、退款、有效期。
- [ ] 任务页展示预扣与最终结算。

**验收标准**

- 同一个 `Idempotency-Key` 不会重复创建任务或重复预扣。
- 账本能解释任一用户余额的来源和每一次变化。

## 8. P6：微信支付与支付宝

**后端任务**

- [ ] 定义 `PaymentProvider` 接口：创建支付、验证回调、查询订单、退款。
- [ ] 实现 WeChat Pay Provider。
- [ ] 实现 Alipay Provider。
- [ ] 实现订单创建、回调验签、金额/订单号校验、回调幂等。
- [ ] 支付成功的同一事务：订单 `PAID` + `CREDIT_GRANT` + Outbox。
- [ ] 先使用沙箱/测试商户完成自动化测试，再启用生产密钥。

**前端任务**

- [ ] 积分商品列表、创建订单、支付跳转/二维码、支付状态页。
- [ ] 仅显示“支付处理中”；最终状态从服务端查询，不信任浏览器跳转页。

**验收标准**

- 重复回调不会重复发放积分。
- 支付成功后用户刷新页面可看到正确余额。

## 9. P7：通知、运营配置与管理后台

**任务**

- [ ] 通知服务消费支付成功、任务成功/失败事件。
- [ ] 实现站内通知；邮件通知按需要接入。
- [ ] 实现管理员登录和 RBAC。
- [ ] 管理积分商品、能力开关、价格规则、任务限制、支付 Provider 开关。
- [ ] 实现任务查询、死信队列处理、积分补偿、订单审计。

**验收标准**

- 用户不能越权查看订单、任务、文件或后台配置。

## 10. P8：安全、测试、观测与发布

### 安全

- [ ] 密码哈希、Token 轮换、CSRF/CORS、限流、验证码频率限制。
- [ ] MinIO 私有 Bucket、短期预签名 URL、文件类型/大小校验、病毒扫描预留。
- [ ] 支付回调验签、金额校验、幂等和审计日志。
- [ ] 日志脱敏：密码、refresh token、支付签名、AI Key、Cookie 均不可记录。

### 测试

- [ ] 单元测试：价格计算、余额计算、状态机、退款、权限校验。
- [ ] 集成测试：MySQL、MinIO、RabbitMQ、Redis 的真实容器测试。
- [ ] 契约测试：OpenAPI 与 FastAPI 路由一致。
- [ ] 端到端测试：注册 → 上传 → 任务 → 结算/退款。
- [ ] 支付回调重复、消息重复、Worker 崩溃、网络超时等故障测试。

### 可观测性与发布

- [ ] 所有请求和消息携带 `request_id` / `trace_id`。
- [ ] OpenTelemetry Trace、Prometheus 指标、集中日志与错误告警。
- [ ] 监控队列积压、任务失败率、支付回调失败、退款量、MinIO 容量。
- [ ] MySQL 备份与恢复演练；MinIO 生命周期和备份策略。
- [ ] 灰度发布、数据库迁移回滚策略和上线检查清单。

## 11. 推荐的首个开发冲刺范围

不要同时开发支付、后台、所有能力。首个冲刺只完成：

```text
Docker Compose（MySQL + MinIO + Redis + RabbitMQ）
邮箱注册 / 登录 / 多端会话
项目与 MinIO 预签名上传
转写任务异步 Worker
积分预扣、成功结算、失败退款
任务轮询页面
```

这条闭环验收通过后，再做微信/支付宝和管理员配置后台。
